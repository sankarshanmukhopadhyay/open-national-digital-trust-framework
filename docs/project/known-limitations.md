# Known limitations

v0.9.0 is candidate quality because its normative surface, traceability and change controls are explicit. Candidate status does not erase enduring or externally evidenced boundaries.

| ID | Candidate limitation | Treatment |
|---|---|---|
| LIM-01 | External independent implementation evidence remains limited | repository-local cross-codebase evidence is disclosed separately from external proof (`URI-01`) |
| LIM-02 | Standards mappings do not create adoption authority | formal selection remains profile-governed |
| LIM-03 | Jurisdiction profiles are not legal advice | competent current review remains required (`URI-03`) |
| LIM-04 | Quantitative defaults are contextual | `CAL-001` records low-confidence provisional values and recalibration triggers |
| LIM-05 | Reference code is not production software | conformance targets observable behaviour, not reference internals |
| LIM-06 | Recognition depends on external authority | `REC-001` demonstrates method only |
| LIM-07 | Protocol/cryptographic choices remain profile-dependent | technology neutrality is retained |
| LIM-08 | Repository validation is not provider certification | qualified `CCL-*` claims are required |
| LIM-09 | External standards change | dependency/change-impact governance remains active |

See the [Candidate Review Programme](candidate-review-programme.md), [Candidate Freeze and Change Control](candidate-freeze-and-change-control.md), and [v1.0.0 Entrance Criteria](v1-readiness.md).
