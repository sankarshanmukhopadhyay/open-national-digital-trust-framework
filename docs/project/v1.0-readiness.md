# v1.0 Stable Specification Readiness

This page records the current repository-controlled readiness of ONDTF for promotion from **v0.9.0 Candidate Specification** to **v1.0.0 Stable Framework Specification**.

The authoritative machine-readable readiness state is [`governance/v1.0-readiness.yaml`](https://github.com/sankarshanmukhopadhyay/open-national-digital-trust-framework/blob/main/governance/v1.0-readiness.yaml). The governing maturity model remains [`governance/maturity.yaml`](https://github.com/sankarshanmukhopadhyay/open-national-digital-trust-framework/blob/main/governance/maturity.yaml).

## Current conclusion

**ONDTF is promotion-ready for a governed v1.0.0 Stable Framework Specification release decision.**

All **nine of nine repository-controlled gates** are evidenced as satisfied. This is an eligibility conclusion, not the release itself: the published framework remains v0.9.0 until an explicit release decision and release transaction occur.

| Gate | State | v1.0 judgment |
| --- | --- | --- |
| Normative stability | `satisfied` | Five normative candidate artifacts are frozen by exact Git blob SHA; material normative change requires impact analysis, evidence invalidation and readiness reassessment. |
| Identifier stability | `satisfied` | Generated identifier validation provides deterministic duplicate and resolution checks. |
| Requirement/conformance traceability | `satisfied` | All 28 candidate requirements are represented in the conformance and requirements machinery. |
| Deterministic validation | `satisfied` | Repository, schema, integration, documentation, publication and v1 stable-governance checks fail closed through CI. |
| Adversarial/negative evidence | `satisfied` | Thirteen consequential failure domains are explicitly covered by executable evidence or governed assessor procedures; orphan coverage is a test failure. |

## Stable-control evidence

The stable specification controls are executable artifacts:

- [`governance/v1.0-normative-freeze.yaml`](https://github.com/sankarshanmukhopadhyay/open-national-digital-trust-framework/blob/main/governance/v1.0-normative-freeze.yaml) binds the proposed stable surface and defines material-change reassessment.
- [`governance/v1.x-change-control.yaml`](https://github.com/sankarshanmukhopadhyay/open-national-digital-trust-framework/blob/main/governance/v1.x-change-control.yaml) defines enforceable compatibility semantics for the v1 line.
- [`governance/errata-and-emergency-change.yaml`](https://github.com/sankarshanmukhopadhyay/open-national-digital-trust-framework/blob/main/governance/errata-and-emergency-change.yaml) governs ordinary and emergency correction, supersession and reassessment.
- [`governance/v1.0-adversarial-coverage.yaml`](https://github.com/sankarshanmukhopadhyay/open-national-digital-trust-framework/blob/main/governance/v1.0-adversarial-coverage.yaml) makes negative-evidence sufficiency explicit across thirteen consequential domains.
- `scripts/validate_v1_stable_controls.py` validates those artifacts and executes deliberate falsification fixtures for normative drift, breaking change without migration, authority-free emergency correction, and an orphan adversarial domain.

The institutional-role catalogue and provider-lifecycle metadata were reconciled from stale draft labels to the v0.9 candidate state before their bytes were admitted to the proposed stable freeze. Their substantive semantics were not changed by that metadata correction.

## Evidence boundary

ONDTF remains at **E1 — repository-controlled reference/executable evidence**.

Promotion readiness does **not** assert:

- independent implementation evidence (E2);
- cross-implementation interoperability evidence (E3);
- operational deployment evidence (E4);
- production readiness;
- certification;
- legal or regulatory approval.

Issue #11 remains a bounded repository-security evidence task. Missing evidence there stays `evidence-required`; it is not converted to PASS and does not currently invalidate the stable specification contract or a repository-controlled promotion gate.

## Promotion and release rule

`promotion_ready: true` is permitted only when every repository-controlled gate required by `governance/maturity.yaml` is present exactly once and has state `satisfied`.

The validators `scripts/validate_v1_stable_controls.py` and `scripts/validate_v1_readiness.py` enforce the stable controls and readiness state. A material normative change, invalidated evidence, superseded implementation assumption or discovered defect can return a gate to `evidence-required` or `blocked` until reassessed.

**Promotion-ready is not released.** The next action is an explicit human-governed v1.0 release decision against this evidence, followed—only if accepted—by the versioned release transaction and its own reproducibility/publication validation.
